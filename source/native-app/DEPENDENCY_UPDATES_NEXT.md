The SDK/toolchain remains 0.45, the PacBrew base remains 0.40.2, and OpenGL stays 1.0.2. curl 8.23.0 and OpenSSL 3.5.9 LTS remain unchanged. FFmpeg keeps libavcodec/libavformat major 61, libavutil 59, swresample 5 and swscale 8, shared by Native/EVO/VLC. VLC remains 3.0.24 with the existing PS5 patches. HarfBuzz's new GPU/raster/vector libraries are not enabled: shaping stays in libass and the app's existing renderer.

`tools/build_maintenance_libraries.sh BASE_SDK WORK_DIRECTORY` builds the isolated, checksum-pinned overlay. The new sub-recipe needs a host CMake and NASM on PATH. A system CMake can be selected with HOST_CMAKE. Base files are never truncated: installations replace overlay leaves. Source/patch/recipe hashes and installed target hashes are checked before linking. Versioned build markers prevent stale package outputs being silently reused after a recipe changes.

The FFmpeg release-download endpoint returned HTTP 503 during preparation, so the recipe pins the official FFmpeg GitHub n7.0.3 source archive instead. It is the same tagged upstream revision, not a different codec fork. The build writes VERSION from the tagged RELEASE file so a build directory inside an app checkout cannot inherit the app’s Git version. The PS5 build already identified itself as 7.0.3; the host fixture build was also normalized and rebuilt. Upstream license texts are refreshed in app/licenses; source URLs and archive hashes are in dependencies.json.

## Selected playback adaptation

Native and EVO now inspect all six bits of HEVC nuh_layer_id and discard non-base-layer NAL units and truncated headers. This keeps HDR10-compatible base pictures from Dolby Vision profile 7 footage while omitting enhancement pictures. VLC already has this filter. Existing repeated-parameter-set filtering and decoder-memory retry behavior are retained. This does not add Dolby Vision output or claim profile 5 conversion.

The behavior was reviewed alongside [Stremio Plus 0.6.00](https://github.com/LoZazaMastro/Stremio-Plus/releases/tag/0.6.00). The EVO adaptation is recorded as a reversible, checksum-verified local patch over pristine 0.13.0 source; see third_party/evo/LOCAL_CHANGES.md.

## Scope decisions

- Keep existing source-cache and seeking protections. Do not import an unrelated player's controller/cache implementation as a library upgrade.
- Keep the working graphics path. PacBrew 0.41.1 mainly changes Mesa/SDL/OpenGL/Vulkan and still packages FFmpeg 7.0.1, so a blanket SDK-library replacement would not address the maintenance gap.
- Defer FFmpeg 9 and libxml2 2.15 API migrations; they need separate compatibility work. Keep the currently tested provider-runtime bundle rather than rebuilding it just for a newer whatwg-url release.
- TrueHD/Atmos passthrough and new HDR output code require a separate HDMI/physical-console acceptance cycle; this batch changes neither output format nor audio transport.
- Tizen-only changes do not apply. MDBList's user_id handling is already present. The newer home-catalog eligibility rule needs a separate review of configured catalogs with server-side defaults, so existing catalog visibility is preserved.

## Verification

See DEPENDENCY_UPDATES_VALIDATION.json for executed results and pinned source/artifact hashes. Host library checks are reproducible with `tests/maintenance_runtime.sh WORK_DIRECTORY`; the codec fixture build uses `tests/build_ffmpeg_maintenance_host.sh WORK_DIRECTORY`. Existing fixture scripts accept HOST_FFMPEG_*, HOST_EVO_FFMPEG_LIBS and HOST_LIFECYCLE_* overrides to select the resulting host libraries. Fixture media should still be generated by the installed full host ffmpeg CLI, not this deliberately limited decoder build.

The checks include production Native/EVO HEVC filtering and decoder-failure cleanup, upstream Expat/libpng tests, real multilingual shaping/rasterization with bundled fonts, the production XMLTV parser, and linked PS5 imports. Physical-console playback with the refreshed libraries remains a tester requirement.
